🔥 PHASE-1 — Docker Explained in Interview Language

When asked "What is Docker?", answer:

Docker is a containerization platform that packages applications with their dependencies into lightweight, portable containers.
Unlike VMs, containers share the host OS kernel, making them faster, smaller, and easier to deploy.

Short version:

Docker lets us run applications consistently across environments.

Images vs Containers
Term	Interview-friendly Definition
Image	Blueprint/template (app + dependencies + runtime)
Container	Running instance of an image
Dockerfile	Script to build images
Registry	Storage for images (DockerHub, ECR, GCR)
Volume	Persistent storage for containers
Network	Communication between containers

📍 Part-3 — Liveness & Readiness Probes (very important)

Add inside your Deployment under containers::

livenessProbe:
  httpGet:
    path: /
    port: 80
  initialDelaySeconds: 10
  periodSeconds: 5

readinessProbe:
  httpGet:
    path: /
    port: 80
  initialDelaySeconds: 5
  periodSeconds: 5

Interview answer:

Liveness probe restarts a pod if container hangs.
Readiness probe ensures traffic isn’t sent until app is ready.
They improve application reliability & avoid failed user requests.

📍 Part-4 — Horizontal Pod Autoscaler (HPA)

Install metrics server first:

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml


Then create HPA:

kubectl autoscale deployment unmilan-webapp --cpu-percent=50 --min=2 --max=8
kubectl get hpa

Load test
kubectl run load --image=busybox --restart=Never -it -- /bin/sh
while true; do wget -q -O- http://unmilan-webapp:80 > /dev/null; done


HPA should increase replica count.

Interview answer:

HPA automatically scales pods based on CPU/Memory or custom metrics.
This is important for SRE reliability & handling traffic spikes.

📍 Part-5 — Kubernetes Interview Q&A

Q1. How does Kubernetes handle failures?

ReplicaSets reschedule pods. Liveness probes restart unhealthy pods.

Q2. How do you debug a failing pod?

kubectl logs <pod>
kubectl describe pod <pod>
kubectl get events


Q3. What happens when a node goes down?

Pods rescheduled to healthy nodes if resources available.

Q4. How do Services work?

They use label selectors to route traffic to backend pods.

Q5. Difference between Deployment, StatefulSet, DaemonSet?

Deployment stateless apps
StatefulSet DB/state apps
DaemonSet runs one pod per node (monitoring/logging)
