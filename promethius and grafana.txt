Q1. What is Prometheus?

Prometheus is a time-series metrics monitoring and alerting system.
It scrapes metrics using a pull model, stores them in TSDB, and queries data via PromQL.

Q3. How does Prometheus collect metrics?

Prometheus scrapes targets at /metrics endpoints.

Q4. What are exporters?

Exporters expose application/system metrics in Prometheus format.
Example: Node Exporter, MySQL exporter, Blackbox exporter.

groups:
- name: system-alerts
  rules:
  - alert: HighCPUUsage
    expr: rate(container_cpu_usage_seconds_total[5m]) > 0.80
    for: 2m
    labels:
      severity: warning
    annotations:
      summary: "High CPU detected"
      description: "CPU usage is above 80% for more than 2 minutes on {{ $labels.instance }}"

# CPU usage
rate(container_cpu_usage_seconds_total[5m])

# Pod restarts
sum(kube_pod_container_status_restarts_total)

# 5xx error rate
rate(http_requests_total{status="500"}[5m])



Q6. How alerts work?

Prometheus rules trigger conditions → Alertmanager routes alerts → Slack/Email/PagerDuty.

Q7. How do you access Grafana?

Port-forward service or expose via NodePort/LoadBalancer.

Example:

kubectl port-forward svc/kind-prometheus-grafana -n monitoring 3000:80

Scenario 1:

CPU is high on one node, what do you do?

Answer:

Open Grafana dashboard → Check CPU usage panel
Use PromQL to find top pods
Scale deployment or analyze workload logs
If recurring, set HPA or optimize resource limits

Scenario 2:

Application latency suddenly increased

Check rate(http_request_duration_seconds_bucket[5m])
Look for errors spike / traffic surge
Check node/pod resource usage
Rollback recent deployment if needed
Alerts notify if SLO breach

Scenario 3:

Too many alerts firing

Tune thresholds
Add cool-down
Create noise-reduction rules
Use SLO-driven alerts, not raw metrics
